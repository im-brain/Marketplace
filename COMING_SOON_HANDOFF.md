## Steps

1. **Back up first.** Create a new branch. Download the live Worker with `GET /accounts/{account}/workers/scripts/heavypockets-coming-soon/content/v2` (a multipart response holding `index.js` and `site.js`) and `.../settings` (bindings and compatibility date). Save them under `site/coming-soon/live-2026-11-04/` and commit. This is the rollback copy.
2. **Make it reproducible.** Add a generator to the repo, for example `site/coming-soon/build.js` in the same no-dependency style as `theme/v3/build.js`. It should produce `index.js` and `site.js` from source files, with assets inlined.
3. **Build and test locally.** Use Playwright, which is pre-installed. Check widths 375, 390, 768, and 1440, landscape, day and night, keyboard use, reduced motion, and 200% zoom. Test the signup against a local mock, including the JavaScript-off form post.
4. **Show Brian a private preview** (a claude.ai artifact, the same as `theme/v3`). Say clearly that the signup can't work inside the preview.
5. **Get Brian's explicit OK before deploying.** This page is public.
6. **Deploy** with `PUT /accounts/{account}/workers/scripts/heavypockets-coming-soon` as multipart: both modules, metadata `main_module: "index.js"`, `compatibility_date: "2025-09-01"`, and `bindings: [{"type": "kv_namespace", "name": "DIBS", "namespace_id": "21d60f8208ca4dcda50fbf2a9bf29af9"}]`. **Leaving out the binding breaks the signups.**
7. **Verify the live page.** Check that `/` shows the new page, that `www.` redirects, and that assets load. Test `/api/dibs` only with requests that write nothing (an invalid email, or the bot-trap field filled in). Don't add test signups to the real list.
8. **If anything breaks, roll back** by re-uploading the backup from step 1 with the same binding.
9. **Update the records:** `CLAUDE.md` (status and session log) and `brand/v2/DECISIONS.md`. Open a PR and don't merge it without Brian.
